The engineering mission

Evidence before
“done”.

The primary engineering priority is reusable, dependable agent tooling. Mooncraft provides meaningful implementation work, real failure modes and a codebase worth keeping maintainable.

Determinism is the foundation. The simulation runs at 20 Hz with validated commands, ordered events, replay verification and canonical state checksums. Presentation observes the simulation; it does not own the truth.

Rust Bevy Deterministic simulation Versioned replays
  1. 01 / Make ownership explicit moonctl tracks work selection, claims, source identity and decision authority. An agent gets a bounded task, not permission to change everything.
  2. 02 / Validate the actual change Fresh validation and independent review are gates to delivery. Proposed capability, fixture evidence and real-world outcomes are kept distinct.
  3. 03 / Keep supervision bounded moond provides opt-in local supervision with finite work limits. It is not an unattended production service or blanket autonomous-delivery certification.

Build the desktop prototype

Install Rust and your platform's linker prerequisites, then use a Bevy-compatible GPU and driver. The game needs Rust 1.95+; these commands select the development toolchain without changing your default.

git clone https://github.com/monk-eee/Mooncraft.git
cd Mooncraft
rustup toolchain install 1.97.0 --profile minimal
cargo +1.97.0 run -p mooncraft-game --locked

Windows is the current graphical development environment. Linux and Apple Silicon macOS are approved targets; native qualification and distributable packages are pending.
